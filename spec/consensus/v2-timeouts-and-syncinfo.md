# V2 timeouts, the round timer, TC formation and SyncInfo

## Rule

**Round timer** (`timer::Timer`, geth `ExpCountDown`). The delay is `period * base^min(cur - qc, max_exp)`, `period = timeoutPeriod` seconds, `cur` the round the timer was reset for, `qc` the round of the highest QC at that moment; `cur - qc` is an unsigned subtraction read as a signed integer, so a QC above the round is exponent 0. The timer is reset by `setNewRound` with `(round, highest QC round)` and, at the end of `initial`, with `(0, 0)`. When the delay passes, geth runs the timeout callback and then restarts the timer with `cur + 1` and the same `qc` (`onTimeout`): a round that keeps timing out waits one exponent step longer each time, up to `max_exp`. The machine has no clock: `SetTimer { token, after }` is the instruction, `Event::Timer(token)` is the expiry, and an expiry with an old token is ignored (geth stops the old `AfterFunc` on every reset).

Parameters. At start the timer is built from the V2 config at round 0: an unset base (`<= 0`) is 2, an unset max exponent (0) is 6, then a base below 1 becomes 1 (`NewExpCountDown`). At every new round `SetParams` takes the config row of that round: the period and the max exponent are always taken, a base below 1 is ignored and the old base stays. All these are reproduced as they are; the pinned networks have only base 1 and max exponent 0 (a flat schedule: 60 s Apothem and net2040, 10 s to 60 s on mainnet), and the vector covers synthetic rows for the other cases. The power is Go's `math.Pow` for a whole exponent, ported (`timer::pow`), because the delay is the truncated product and a last-bit difference would change a nanosecond.

**Timer expiry** (`OnCountdownTimeout`). A key that is a masternode of the head's epoch signs the timeout of the current round and sends it (`sendTimeout`): the gap number comes from the chain (`Chain::timeout_gap`), the intent is `(Timeout, round, sigHash(round, gap))`, and it goes through the safety unit. A repeat of the same timeout is a replay: no write, same signature (geth sends it every period). If the timeout was sent, the count of the round goes up, and every `timeoutSyncThreshold` timeouts (the config of the current round) the node sends `SyncInfo { highest QC, highest TC }` (xOneGo #623). A threshold of 0 makes geth divide by zero; here it sends no periodic SyncInfo. The count is reset at each new round. The timer restarts whatever happened.

**Timeout handling** (`timeoutHandler`). Only a timeout of the current round counts, and the test comes before any signature work. The signer must be in the candidate pool of the gap snapshot (`NextEpochCandidates`, not empty). The pool keeps one timeout for each signer and round. Two gates: the distinct signers of this `(round, gap)` that are masternodes of the head's epoch reach the threshold of the round's config; then the signers that are masternodes of the epoch that holds the round (`getTCEpochInfo`) reach it again. Then the TC is `{round, one signature for each signer, gap}`, `processTC` runs (highest TC, and the node enters `round + 1` if the TC's round is at least the current one), and the node sends its SyncInfo (`timeout.go:214-216`). The timeout pool is cleared at each new round.

**SyncInfo origination.** After a TC, and at every `timeoutSyncThreshold`-th timeout of a round (above).

**SyncInfo handling** (`VerifySyncInfoMessage`, `SyncInfoHandler`). In this order, and nothing is changed until the last step: (1) a SyncInfo that is not newer than the local highest QC and highest TC is dropped without a score (honest peers send what they have); (2) more than 150 signatures in the QC, or in a TC that is not blank, is refused before any signature work (`ScorePeer: Oversized`, CertiK P3, geth PR 1731); (3) the QC is verified in full: the masternodes of the epoch of its block, the threshold of its round, the gap number of that epoch, the header and its number and round; (4) the TC is verified, except the blank bootstrap TC of a sender that has seen no timeout (round 0, no signature); (5) only now `processQC` and then `processTC`. A failed check of a signature, a member, a threshold, a gap or a block info is `ScorePeer: Invalid` and the state is exactly as before; a block or an epoch the node does not have is not the peer's fault: no score, no change. A QC that passes with a TC that fails changes nothing: the QC is not applied. (The erigon EX-1 defect applied the QC of an unverified SyncInfo and persisted the round.)

**Entering a round** (`setNewRound`). The config of the round is looked up (a round without a config is an error), the count of timeouts is 0, the timer is set up with that row and reset, the timeout pool is cleared, the vote pool drops the rounds more than 10 behind, and the machine emits `AdvanceRound { round, mine_period }` and `SetTimer`. `mine_period` is `minePeriod` of the config row of that round, read from the chain spec: a devnet with `minePeriod = 1` gives 1, not a built-in 2 (xOneGo #721). The producer waits that many seconds after the parent before it seals; the header verifier uses the same row (`verify/header.rs`).

**Seeding** (`initial`). The machine starts from the chain head: at the V2 switch block the highest QC is the round-0 QC of that block and the round is 1; above it the highest QC is the one the head carries and the round follows from `processQC` (the lock QC and the commit are seeded the same way); the timer is reset with `(0, 0)`; the safety record is the one the store loaded. A head below the switch block leaves the machine unseeded and every event but `Synced` is dropped; the first event after the chain has crossed the switch seeds it. geth starts with a placeholder highest QC (no block) and raises it only by round, so a head whose QC is the round-0 QC of the switch block leaves the placeholder in place, and a SyncInfo made from it names no block: no peer can verify it. Here the first QC replaces the placeholder (the simulator found it: seed 436 of `sim/`, a validator restarted on the first V2 block could never bring the others past a TC that they had missed). The driver also keeps the SyncInfo of the node (`Effect::Store`: the highest QC and the highest TC, whenever either is raised; chaindata, not the safety record) and feeds it back at start as a SyncInfo of the node to itself; it is verified like any other. Without it a QC or TC that the node formed, which is in no block until a leader includes it, is lost with the process: a node that timed out in round r+1, restarted in round r and lost that certificate cannot sign a timeout for round r (the record is at r+1, ADR-010 section 7), and when the other validators need that timeout for their own TC of round r the network stops. The simulator found it twice: seed 806 (a QC; 5 validators, one Byzantine, quorum 4) and seed 1983 (a TC; 4 validators, one Byzantine, quorum 3). geth does not stop here because it has no such bound on timeouts; ADR-010 open question 1 should be answered with this in view. Nothing is seeded by an import: the epoch of a block is derived by the `Chain` implementation from the parent walk. A validator that joined mid-V2 or crossed the switch through sync votes and times out like one that imported every block (xOneGo #718: its driver rejected every vote and timeout with `ErrV2MasternodesUnavailable`).

## Networks

All with V2. The schedule rows: mainnet 7, Apothem 5, net2040 1, devnet 2, devnet551 3 (`crates/xone-chainspec/generated/forks.json`).

`xone_consensus::v2::{timer::Timer, bft::timeout, syncinfo::{originate, MAX_PEER_SIGNATURES}}`, `Bft::{set_new_round, process_tc}`.

## Vectors

- `conformance/vectors/v2/bft-timer.json` (oracle command `timer`, the pinned `createEngine`, `setNewRound`, `Reset`, `GetTimeout` and `onTimeout` through an overlay): every V2 config row of the five built-in networks (including net2040) at its first round, the next, and a later one, with the highest QC 1, 2, 5 and 300 rounds behind, and five expiries after each; plus synthetic rows (bases 1.1 to 2, max exponent 3 to 20, a base below 1, an unset base, a QC above the round) and an unset first row. 300 steps, 63 distinct delays. `tests/bft_vectors.rs::the_timeout_schedule_equals_geth_for_every_config_row` also checks that each real row in the vector is the row of the chain spec.
- `tests/bft_machine.rs`: `syncinfo_is_sent_after_every_timeout_sync_threshold_timeouts` (thresholds 2, 3, 5; the SyncInfo is sent at timeout `i` iff `i % threshold == 0`), `a_timeout_is_persisted_signed_sent_again_and_the_timer_restarts`, `enough_timeouts_make_a_tc_move_the_round_and_send_syncinfo`, `a_syncinfo_that_does_not_verify_changes_no_state_and_scores_the_peer` (EX-1: nine forged or under-threshold SyncInfo, each leaves round, QC, TC, record, pools and commit as they were and scores the peer), `a_validator_that_crosses_the_switch_through_sync_votes_and_times_out`, `a_validator_that_joins_mid_v2_seeds_round_qc_and_lock_from_the_head`, `the_mine_period_of_the_config_drives_the_round_effect`.

## Not covered

- The walk back to an earlier epoch for a TC of an older round (`getTCEpochInfo`'s loop) is `Chain::epoch_of_round`.
- A QC whose gap number does not match the epoch but indexes a snapshot with the same signer set (`utils.go:373-396`, a bulk-sync device of this fork) is refused here.
- The 60 s `periodicJob` is replaced by pruning at each new round.
