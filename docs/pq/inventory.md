## How to read this

- Evidence tag at the start of every Notes cell. **observed**: read in code at the pin or in this repository. **inferred**: follows from observed code but was not run. **unknown**: not determinable from the pinned tree; the row says what would settle it.
- Part A is what exists on XDC networks and in the geth-XDC client at the pin (IDs `T01..`). Part B is what the xOne rebuild plans or already contains (IDs `P01..`). A surface can appear in both parts.
- "Public key exposure": when the key that verifies a signature becomes known to an observer. For ECDSA with `ecrecover` the public key is recovered from the first signature, so "revealed on first use" means the first signed message.
- "Message domain and separation": what keeps a signature for one purpose from being valid for another. Where the answer is "structural", no explicit tag exists: the only separation is the shape of the hashed RLP. Nothing in XDC hashes a context string or a chain ID into votes, timeouts or seals (see the threat model, section 7).
- "Consensus-critical": `y` if a different result changes block validity or state and so forks the chain; `n` otherwise. Wire-only surfaces are `n` for consensus but a change still needs a coordinated release.
- Default curve everywhere unless stated: secp256k1 ECDSA, 65-byte `r || s || v` recoverable signature, 32-byte Keccak-256 digest, address = `keccak256(x || y)[12:]` (`crypto/crypto.go:253`, `core/types/transaction_signing.go:509`).

## C. Measurements and arithmetic used by the other documents

- **V2 QC size in headers (measurement).** Input: `conformance/vectors/headers/apothem.jsonl` (2,000 headers) and `net2040.jsonl` (500), exported 2026-11-11; only V2 headers (1,041 and 426) whose `extraData` decodes as version byte `2` plus `ExtraFieldsV2`. Method: decode the RLP, take `quorum_cert.signatures`, check every entry is 65 bytes. Result: Apothem QC signatures per header min 0, median 21, max 78; `extraData` median 1,471 bytes, max 5,290. net2040: median 8, max 13; `extraData` median 596, max 931. Minimum 0 is a header whose QC carries no signatures (early rounds).
- **Arithmetic, not measurement.** At 78 signatures per QC, 65-byte ECDSA signatures take 5,070 bytes; the same count of ML-DSA-65 signatures (3,309 bytes each, FIPS 204 Table 2) is 258,102 bytes per header, plus the QC's other fields. Threshold rule: with 108 masternodes and `CertThreshold` 0.667 (`utils.go:365-376`) the QC needs at least 73 signatures.
