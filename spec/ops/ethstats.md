# ethstats: the stats-board client and its frames

Lines are `XDCIndia/go-ethereum` `ethstats/ethstats.go` (`ethstats.go`). Rust: `xone_node::observe::ethstats` (frame builders are pure functions; `Ethstats` is the `Service`). Frames are compared byte for byte with `crates/xone-node/tests/fixtures/ethstats/golden.tsv`, which `golden_gen.go.txt` writes by marshalling the structs of `ethstats.go:489-505, 539-543, 656-679, 838-870` with the real `common.Hash` and `common.Address`. It was run once against the pinned source, never against a live board.

**Envelope.** Every message is `{"emit":[event,payload]}` sent with `conn.WriteJSON` (`:583`, `:622`), so it is one text frame ending in the encoder's newline. Payloads that are Go maps list keys sorted (`id` after `block`, `clientTime` before `id`); payloads that are structs list keys in field order. The Rust builders write both orders by hand.

**Login (`:546-597`).** `hello` with `{id, info, secret}`. `info` keys, in order: `name, node, port, net, protocol, api, os, os_v, client, canUpdateHistory, coinbase, role, syncMode, gcMode, stateScheme` (`:489-505`). `name` and `id` are the node name from the URL, `node` and `client` the one build stamp (xOneGo `525ed5b1`, `d8ff9d9c`: the pin hard-codes `"0.1.1"` for `client`, which was the stale-version bug), `api` is `"No"`, `os_v` the architecture. `coinbase` and `role` come from the live signer (`coinbaseAndRole`, `:529-537`): lowercase 40-hex address and `"validator"` only when the node is authorised and sealing, else the zero address and `"follower"` (xOneGo `e2560360`, `6acb9280`). The server answers `{"emit":["ready"]}` (`:590`); anything else is `unauthorized`. A bare `"primus::ping::<t>"` string before or after must be answered with `"primus::pong::<t>"` (`:414`).

**Reports.** `report` (`:599-615`, on connect and every 15 s, `:360-ish` ticker): `node-ping`, `block`, `pending`, `stats`. A new head sends `block` and `pending` at once (`:371-376`).
* `node-ping` `{clientTime, id}`; on `node-pong` the client sends `latency` `{id, latency}` with the half round trip in whole milliseconds **as a string** (`:617-654`). `clientTime` is Go's `time.Time.String()`; the server does not parse it back.
* `block` `{block, id}` with `number` (number), `hash`, `parentHash`, `timestamp` (number), `miner` (lowercase hex), `gasUsed`, `gasLimit` (numbers), `difficulty` (string), `totalDifficulty` (`"0"`, `:773`), `transactions` (`[{"hash"}]`, `[]` when empty), `transactionsRoot`, `stateRoot`, `uncles` (`[]`, `uncleStats` forces an empty array not null) (`:656-679, 716-789`).
* `pending` `{id, stats:{pending}}` (`:838-860`).
* `stats` `{id, stats:{active, syncing, peers, gasPrice, uptime}}`: `uptime` is the constant 100, `gasPrice` an integer (`:863-910`). The pin has **no** `mining` or `hashrate` key; xOne sends none, so the frame equals what XDC nodes send. (The task text listed them; they are not in the pinned source.)
* `history`: on `{"emit":["history",{"list":[n..]}]}` reply `{history:[block..], id}`; no list means the top 50 (`historyUpdateRange`, `:51`). The reply is newest first and stops at the first unknown number (`:791-835`).

**Reconnect.** geth waits 10 s after a failed dial or login (`:307-340`). xOne backs off 1 s doubling to 60 s and resets after a session of 30 s or more; the wait is cancellable in 100 ms steps. Head reports are bounded by a `TokenBucket` (10 burst, 5/s). Read timeout 500 ms, so stop takes under about a second plus the connect timeout (3 s).

**xOne rules beyond geth** (issue #41 supplement). TLS by default: a URL without a scheme is `wss://host/api`, and there is no fallback to `ws://` after a TLS failure (xOneGo tried `wss` then `ws`). `ws://` needs `allow_plaintext` (private devnet), else `start` fails. The URL holds the secret: `Debug` prints `<redacted>`, errors never echo the URL. Telemetry runs on its own thread over plain-read traits (`ChainStats`, `PeerStats`), so a slow or dead server never touches import.

**Not done.** `block_new_payload` (`:696-714`) is not sent. A name containing characters Go escapes (`<`, `>`, `&`) is escaped the same way; other Unicode is not escaped by either side.
